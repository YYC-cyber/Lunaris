# 角色配图方案说明（朋友圈配图）

> 本文档记录 Lunaris 朋友圈配图（MOM-02）的**当前实现方案**与**未来增强路线**。
> 核心目标：让 AI 角色在朋友圈里发「**自己**」的图片（角色一致），而不仅是「任意生成的图」。

---

## 一、当前方案（免费，已上线）

**技术**：Pollinations.ai 免费文生图（免 key），兜底接入 `clients/image_client.py`。

### 工作流程

```
moments_task 发动态
  └─ image_client.generate("一张晚上的朋友圈配图，露娜的日常，风格温馨自然")
       ├─ 配了 IMAGE_API_KEY → Gitee AI 真生成
       └─ 没配（当前）→ Pollinations 免费生成 → URL
```

### 当前效果与局限

| 项 | 状态 |
| --- | --- |
| 朋友圈能带图 | ✅ 有真生成的图 |
| 免费 / 免 key | ✅ |
| 图与文案相关 | 🟡 大致相关（按提示词自由发挥） |
| **角色一致**（每次长一样） | ❌ **做不到**——纯文生图无参考图，同一角色每次脸/衣服都不同 |

---

## 二、目标方案（角色一致，未来增强）

**关键**：想让角色每次长一样，必须用**参考图生成**（reference image）——提供角色的一组照片，生成时带上，模型保持该角色长相。

### 技术路线（2 选 1）

| 路线 | 说明 | 成本 |
| --- | --- | --- |
| **A. 支持参考图的云 API**（推荐） | 硅基流动的 IP-Adapter 类模型、通义万相 reference 模式——每次生成带参考图 URL | 按量付费（比 VISION 便宜） |
| **B. 自建 ComfyUI + IP-Adapter/LoRA** | 运营方服务器跑 ComfyUI，导入角色 LoRA | 免费但重（需 GPU） |

### 需要准备的素材（每个角色一套）

```
backend/data/souls/{name}/ref/
├── ref_1_fullbody.png    # 全身照：正面、完整、无遮挡、背景干净
├── ref_2_halfbody.png    # 半身照：看清脸、发型、上衣
├── ref_3_side.png        # 侧面/另一角度：确认发型轮廓
└── appearance.md         # 角色外观描述（详细文字）
```
要求：    
  - 全身图：人物完整、无遮挡、无其他人/杂物、背景干净（纯色或简单）
  - 多角度：至少 正面全身 + 正面半身 + 侧面，让模型知道「这个人长什么样」
  - 外观一致：所有参考图的发型/发色/瞳色/服装风格统一
  - 外观描述：appearance.md 写清楚——发色、瞳色、脸型、身高体型、常用穿搭、气质（这个正好接我们之前聊过的「形象设定」）

**参考图要求**：
- 全身图人物完整、无杂物、无其他人；背景简单
- 多角度（正面全身 + 正面半身 + 侧面）
- 所有参考图**外观一致**（发色/瞳色/发型/穿搭风格统一）
- 分辨率和清晰度够用（建议 512px+）

**appearance.md 示例**：

```markdown
# 露娜 外观描述

- 发色：浅金色双马尾，发尾微卷
- 瞳色：天蓝色，圆眼，笑起来弯弯的
- 脸型：圆脸，娃娃脸，带点婴儿肥
- 身高体型：160cm 左右，娇小
- 常用穿搭：白色连衣裙 / 粉色卫衣 + 短裙，白袜帆布鞋
- 气质：元气可爱、学生气、清纯甜美（真人感，非二次元）
```

### 生成时如何组合（路线 A 示例）

```
prompt = 外观描述 + 场景描述（"露娜在咖啡店喝奶茶，全身照"）
        + 参考图（ref_1/2/3）传给支持参考图的模型
→ 生成「还是那个露娜」的新图
```

## 三、角色外观描述（已预留位置）

每个角色的 SOUL.md 已可加「形象设定」section，用于：
- 文生图的**外观提示词**（当前阶段用）
- 参考图生成时的**外观描述**（未来阶段用）

示例（加到对应 SOUL.md）：

```markdown
## 形象设定（供朋友圈配图生成）
- 风格：真人照片（写实摄影，禁二次元/插画/3D）
- 外貌：{发色/瞳色/脸型/身高体型}
- 穿搭：{常用服装}
- 场景：家 / 咖啡店 / 街角 / 日落
```
